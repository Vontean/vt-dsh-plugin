## 0. 一句话

**低保真的信号只放在「内容与外观」层，排版与节奏按高保真做。** 虚线说「这块还没定」，灰块说「内容还没定」，角标说「这是模拟出来的屏幕」；字号、行高、间距、对齐、圆角按最终品质给，不做手绘质感、不做纸纹、不做涂鸦。

风格方向：Notion 式的**线面语言** —— 用 1px 线与浅灰面建立层级，不用重阴影、不用渐变、不用装饰性插画。

### 0.1 为什么这样切（依据）

引自上位 spec 的三条结论：

| 结论 | 出处 | 对本文的约束 |
| --- | --- | --- |
| 低保真与高保真在「发现结构性问题」上等效 | Walker 2002 | 所以低保真稿的功能是**讨论结构**，把它做贵不增加信息 |
| 低保真降低设计者沉没成本依恋，评审者更敢提意见 | NN/g 2016 | 所以草稿必须**看得出来是草稿**，否则评审开始挑视觉细节 |
| 低保真会被高估美感，不能用于评视觉质量 | Sauer 2009 | 所以交付时必须声明「这不是视觉稿」，见 §8.3 |

反过来还有一条推论：**低保真不等于排版可以糙**。字号跳档、奇数间距、基线不齐会制造「这个方案不成熟」的错觉，把讨论从结构带偏到「你这里怎么歪了」。这就是本文把内容层压到低保真、把排版本层抬到高保真的原因。

线框稿（wireframe）作为流程惯例可追到 1990 年代末的网页设计实践，本文不复制那种时代的视觉表征（斜线填充、手写体标注、纸纹），只保留「未定 vs 已定」这一个信息。

## 1. 与 DESIGN.md 的关系

`DESIGN.md` 是既有体系，本文**只继承、不覆盖**。

| 类别 | 处理 |
| --- | --- |
| 颜色 | 全继承：只用 `--dsl-g-*`（已包好宿主 `--dsw-alias-*`）与宿主 token，不写死 HEX |
| 字号阶梯 | 继承 12/13/14/15/18/24/28/36/40，本文只用其中 12/13/14/18 |
| 字重 | 继承 400/500/600 三档，不引入 700+ |
| 间距 | 继承 4/8/12/16/24，**不新增 20/32/40** |
| 圆角 | 继承 6/8/12/999 |
| 表面与阴影 | 继承「内联面一律无阴影、只有真正浮起的元素才有阴影」 |
| 线色 | 继承「不自调百分比，只用宿主 alias」 |
| 动效 | 继承 `cubic-bezier(.22,1,.36,1)` 与 `prefers-reduced-motion` 分支 |

**冲突仲裁**：任何与 `DESIGN.md` 撞车的取值，以 `DESIGN.md` 为准，并在 §10 记录差异。本文只新增「原型通道专用」的 8 个组件的规格（切片 2 增加了 `modal`），以及 1 个新时长（§6.6 脉冲）与 1 个遮罩取值（§6.8）。**不改 `GenuiBlock.module.css` 的 token 段，也不改现有 50 个组件**——新组件是独立 CSS 模块，只消费既有变量。

### 1.1 为什么不复用 24 / 28 / 36 这些档

原型里最大的字是页标题。放到 24 会与回答自身的标题（`text.h1` 24/600）抢同一层，读者分不清「回答结构」与「原型结构」。18/600 足够在卡片内建立第一层，也不越界。数据型大字号（stat / mega）属于「把数据说清楚」的场景，原型不用。

### 1.2 排版高保真在哪、低保真在哪

| 层 | 保真度 | 具体 |
| --- | --- | --- |
| 内容 | 低 | 真实文案可以留空，用灰块或短词占位 |
| 外观 | 低 | 无品牌色实心、无渐变、无插画、无真实照片 |
| 排版 | **高** | 字号/行高/字重/字距/对齐按最终品质 |
| 节奏 | **高** | 间距只走 4 的倍数刻度，同级元素同间距 |
| 布局 | **高** | 对齐线明确，栅格关系一眼可读 |

## 2. 线面语言

### 2.1 线宽只有一档：1px

| 名称 | 宽度 | 用在哪 |
| --- | --- | --- |
| hairline（细线） | 1px | 行分隔、区段分隔、导航底边 |
| 边框 | 1px | 页面外框（虚线）、控件描边、占位区域框 |
| 分隔线 | 1px | 同 hairline，差别只在**位置与角色**，不在宽度 |

三档在**宽度上是同一个值**，区分靠**线色**与**位置**。这是刻意的：

- 不写 `0.5px`：宿主全线是 1px，混入亚像素线在非整数 DPR / 缩放下会被取整成 0 或 2px，同一屏出现两种粗细。
- 不写 `2px` / `3px`：加粗描边在低饱和线面语言里会读成「选中」或「警告」，与状态语义抢意思。纯视觉的加粗一律不加。

唯一例外：**焦点环** `outline: 2px solid var(--dsl-g-accent); outline-offset: 2px`。它属于可访问性，不是装饰，也不占布局。

### 2.2 线色三档

| 档 | token | 浅色解析 | 深色解析 | 用途 |
| --- | --- | --- | --- | --- |
| 分隔 | `--dsl-g-border`（→ `border-l1`） | 黑 4%（≈ `#f5f5f5`） | 白 6%（≈ `#38383a`） | 行分隔、区段分隔、导航底边/右边 |
| 结构 | `--dsl-g-border-strong`（→ `border-l2`） | 黑 10%（≈ `#e6e6e6`） | 白 12%（≈ `#454547`） | 页面外框（虚线）、控件描边、占位区域框 |
| 状态 | `--dsl-g-accent` / `--dsw-alias-state-error-primary` | `deepseek-500` / `red-600` | `deepseek-400` / `red-400` | 焦点环、当前项图标、invalid 描边与错误文本 |

「解析」列只是核对用的参考值，**代码里一律写 `var(...)`**。

**禁止**：用 `color-mix()` 把 label 色按百分比调出一档灰当线色。DESIGN.md 记过这个坑（12% 比宿主 hairline 深约 3 倍，就是「描边太粗、灰太重」的来源）。要更深的线，只有 `border-l2` 这一档，没有第三档可调。

### 2.3 虚线：只标「这块不是真实界面」

虚线是本文最锋利的一把刀，**只切一种东西**：还没成为真实界面的边界。

| 该虚 | 为什么 |
| --- | --- |
| `page` 外框 | 这个矩形是**模拟出来的屏幕**，不是宿主真实界面的一部分 |
| 区域占位框（短边 ≥ 64px） | 这块区域的**结构还没定**，等讨论 |

| 不许虚 | 为什么 |
| --- | --- |
| 行分隔线、区段分隔线 | 分隔是已确定的结构；虚线会让人以为「这一行还没做完」 |
| `nav` 任意形态（含底边、右边） | 导航位置已定 |
| 按钮、输入框、字段组、标签 | 控件轮廓已定；控件是虚线 = 「这个控件是假的」，与「内容未定」混淆 |
| `list-row` 的媒体位（40px） | 见 §3.2 的 64px 规则：小尺寸虚线读起来是噪点，不是信号 |
| `empty` / `loading` 本体 | 它们是**真实状态**，不是草图占位（见 §3.4） |
| 卡片面、弹层 | 表面已定 |

参数：`border: 1px dashed <结构线>`。**不自研 `stroke-dasharray` 或背景图虚线**——浏览器原生 dash 节奏（约 3:1）在各平台略有差异，但比自研的多一套要维护的节奏更稳。虚线允许出现在圆角容器上，直接跟着 `border-radius` 走。

### 2.4 面：四级，靠层差与描边分工

| 级 | 语义 | token | 浅色 | 深色 | 层级怎么来 |
| --- | --- | --- | --- | --- | --- |
| 0 背景面 | 会话底 | 透明（继承宿主） | 白 | 近黑 | — |
| 1 卡片面 | `page` 屏幕底、弹层内容底 | `--dsw-alias-bg-layer-2` | 白（与背景同色） | `#2c2c2e` | 浅色：靠 1px 虚线/描边；深色：靠层台阶 |
| 2 内嵌面 | 侧栏底、输入框底、禁用控件底 | `--dsw-alias-markdown-code-block` | `#f9fafb` | `#1b1b1c` | 深浅都靠层差；不额外描边 |
| 3 悬浮面 | 后续 `modal`、现有 tooltip/toast | `--dsw-alias-bg-layer-3` + `--dsl-g-shadow-float` | 白 + 阴影 | `#353436` + 阴影 | 唯一允许阴影的层级 |

两条硬规则，来自 DESIGN.md §3.1：

1. **浅色下卡片面与背景面同色**，层级必须由线承担（所以 `page` 即使铺了面也要有外框）。不要去把面调暗来「显得有层级」——卡片比页面暗会读成凹陷/禁用。
2. **描边与阴影不叠加**。内联面（page / nav / 行）只有线；只有 `modal` 同时有面 + 阴影，因为它真的浮起来了。

内嵌面在浅色下与白底只有 1.05:1 的对比，肉眼近乎不可见 —— 它靠**位置**（贴边、整块）与**相邻的线**被识别，不靠自身深浅。这是宿主语言的一部分，不要为了「看得见」去加深它。

## 3. 低保真专用信号

三个信号，各管一件事，**互不替代**：

| 信号 | 管什么 | 形态 |
| --- | --- | --- |
| 区域角标 | 「这是模拟出来的屏幕」 | 贴着 `page` 外框上边的一枚小标签 |
| 虚线框 | 「这块区域的结构还没定」 | 1px dashed，短边 ≥ 64px |
| 灰阶块 | 「这块内容是占位」 | 无边框的浅灰实心块 |

### 3.1 区域角标

```
高度 18 / 左右内边距 6 / 圆角 6
字号 12 · 行高 18 · 字重 500 · 颜色 label-secondary
背景 = 背景面（--dsw-alias-bg-base），用来把下面的虚线「切开」
位置：水平左缩进 12；垂直居中压在外框上边线上（外框容器 padding-top: 9px）
```

- 文案格式：`屏 1 · 任务列表`。屏序号用阿拉伯数字，分隔符用 `·`，不加大写、不加字距。
- **为什么背景要用 `bg-base`**：角标压线，若背景透明，虚线会从字里穿过去，读起来像排版事故。用「线后面的那个面」填住，是唯一的正解。
- 角标的左缩进 12 与内容左缩进（24/16）**不强制对齐**：它是外框的标注，不是内容的一部分，压线关系比对齐更重要。
- **层级**：`z-index: 2`。`page` 一旦成为定位上下文（浮层需要），角标会被压住——实测过，浮层一出现角标下半截就被吃掉了。
- `split` 里比较两个方案时，每栏各带自己的角标（`方案 A · 空态` / `方案 B · 加载态`）。**角标是区分方案的唯一手段**，不要再加彩色标题条或底色区分。

### 3.2 占位块

分成两种，别混用：

**区域占位框**（结构未定，有边界）

```
1px dashed 结构线 / 圆角 8 / 底 = 灰块色 / 内字 12·18·400·label-tertiary
适用：图片位、图表位、整块待定内容区
约束：短边 ≥ 64px。小于 64px 一律改用灰块（40px 的虚线框在真实渲染里只是噪点）
```

**内容灰块**（内容未定，无边界）

```
无边框 / 圆角 6（文本条）或 8（媒体位）/ 底 = 灰块色
适用：文本占位条、40×40 媒体位、头像位、骨架屏
尺寸档：文本条高 12；媒体 40×40；宽度百分比只用 100 / 72 / 56 / 88 / 76（见 §6.6）
```

灰块色：`color-mix(in srgb, var(--dsw-alias-label-primary) 7%, transparent)`。
在浅色下落在白底上是 `#eeeeef`（1.16:1），深色下落在卡片面是 `#3a3a3c`（1.23:1）。
**它不是信息通道**，是纹理信号，所以 1.1:1 量级的对比是设计意图，不是失误 —— 因此它必须 `aria-hidden`，不能承载只有它才有的信息。

### 3.3 刻意不做的事（禁止清单）

- 不做手绘质感：纸纹、便签、订书钉、胶带、手写体。
- 不做斜线/网格填充（那是"图片占位"的老符号，在浅灰面语言里会立刻变重）。
- 不做涂鸦箭头、批注气泡、"在此处？"之类的设计师口吻标记；要看标注走 `minedesign` 的标注层，不进 DOM。
- 不做「草稿」印章、水印、`SKETCH` 角标贴纸。
- 不给整块加灰度滤镜或降低不透明度来「显草」——那会把文字对比度一起拉低，违反可读性。
- 不用 emoji 代替图标位（`🖼` 这类），用 `icon` 组件的 Lucide 图标或灰块。

### 3.4 `empty` 与 `loading` 不是草稿信号

这两个是**真实状态**，必须按成品做：

- `empty` 的外框是实线（若有），图形位用灰块而不是虚线框——「这里以后会有插画」是内容占位，不是结构未定。
- `loading` 的骨架是灰块 + 脉冲，不是虚线框。
- 判据：把 `empty` 的截图给用户看，他应该说「这是没有数据的样子」，不能说「这是还没画完」。

## 4. 排版

### 4.1 字号 / 行高 / 字重 / 颜色

字距一律 `letter-spacing: 0`（中文不需要，拉丁在本规范的 ≤18px 区间也不该调）。行高用**具体像素值**，不用无单位倍数——同一档字号在不同位置算出半像素，会出现「同一级文字看着不一样高」。

| 角色 | 字号 | 行高 | 字重 | 颜色 | 用在哪 |
| --- | --- | --- | --- | --- | --- |
| 页标题 | 18 | 24 | 600 | label-primary | `page` 标题 |
| 页副标题 | 13 | 20 | 400 | label-secondary | `page` 副标题 |
| 区段标题 | 13 | 20 | 600 | label-primary | 页内分组（`pr-section` 式结构） |
| 行主文本 | 14 | 20 | 400 | label-primary | `list-row` 主文本 |
| 行副文本 | 13 | 18 | 400 | label-secondary | `list-row` 描述 |
| 行尾元信息 | 12 | 18 | 400 | label-secondary | 时间、状态字 |
| 字段标签 | 13 | 20 | 500 | label-primary | `field-group` 标签 |
| 字段提示 | 12 | 18 | 400 | label-secondary | 说明、占位提示语 |
| 字段错误 | 12 | 18 | 400 | state-error-primary | 校验失败信息 |
| 导航项 | 13 | 20 | 500 | label-secondary（当前项 label-primary） | `nav` 顶栏/侧栏 |
| 底部标签 | 12 | 18 | 500 | label-primary（当前项图标 accent） | `nav` 底部 |
| 按钮 | 13 | 20 | 500（主操作 600） | label-primary | 控件 |
| 空态标题 | 14 | 20 | 500 | label-primary | `empty` |
| 空态说明 | 13 | 20 | 400 | label-secondary | `empty` |
| 区域角标 | 12 | 18 | 500 | label-secondary | 外框标签 |
| 占位字 | 12 | 18 | 400 | label-tertiary | 占位框内的「图」这类字符 |

**三级文字的分工（重要）**：

- `label-primary`：要读的内容。
- `label-secondary`：**所有可读的辅助文本**都用它。12px 下它是唯一合法的辅助色（浅色 5.80:1）。
- `label-tertiary`：只给**非信息性**字符（占位框里的「图」）。它浅色只有 3.71:1，低于小字号文本 4.5:1 的要求 —— 这条是实测结果，见 §7.2。

### 4.2 对齐与断行

- 正文一律左对齐，不做两端对齐（中文两端对齐会产生不规则字距）。
- 行主文本/副文本**单行截断**（`overflow: hidden; text-overflow: ellipsis; white-space: nowrap`）。原型里换行会让行高跳动，讨论时看不清列表节奏。
- 数字用等宽数字（`.block` 已设 `font-variant-numeric: tabular-nums`，新组件继承，不要再关掉）。
- 居中只出现在 `empty`（整块居中）与角标文字；正文不居中。
- 页标题栏的文字列 `flex: 1; min-width: 0`，尾部操作 `flex: 0 0 auto` —— 窄下来先压文字，不压按钮。

### 4.3 间距刻度

只用 4 / 8 / 12 / 16 / 24。**不新增 20 / 32 / 40**，需要「更大一档」时用「24 + 一条线」而不是更大的留白——线面语言里，分隔靠线，不靠空白堆。

| 值 | 用在哪 |
| --- | --- |
| 4 | 标题与副文本、主文本与副文本、标签与提示 |
| 8 | 图标与文字、尾部元素之间、侧栏项之间、角标内边距 |
| 12 | 行内媒体与文本、区段标题与内容、区段头内部 |
| 16 | `page` 标题栏内边距（上下）、区段内边距（上下）、控件之间、`split` 栏间距 |
| 24 | 页面水平内边距（宽容器）、区段之间的分隔节奏 |

窄容器（`≤600`）把页面水平内边距从 24 降到 16，**其余间距不变**——收缩只发生在容器边距上，不动内部节奏。

### 4.4 圆角

| 档 | 值 | 用在哪 |
| --- | --- | --- |
| 页面/弹层 | 12 | `page` 外框、`modal` |
| 控件 | 8 | 按钮、输入框、导航项、占位区域框、媒体位 |
| 小 | 6 | 文本占位条、区域角标、行内代码块 |
| 胶囊 | 999 | 头像（`list-row` 媒体位 `data-shape="circle"`） |

不做「大圆角软卡片」（16/20/24）。圆角超过 12 在 760px 的对话列里会显得像手机壳，而不是屏幕。

### 4.5 控件尺寸

| 元素 | 尺寸 |
| --- | --- |
| 按钮 / 输入框 / 导航项高度 | 32 |
| 导航顶栏高度 | 48 |
| 底部标签高度 | 52（窄容器 48） |
| 侧栏宽度 | 200（窄容器转为横向条，高度自适应） |
| 行高（`list-row`） | 56（有副文本）/ 40（只有主文本） |
| 媒体位 | 40 × 40 |
| 图标 | 16（行内、导航项）/ 20（底部标签），Lucide，`stroke-width: 1.5` |
| 角标 | 高 18 |

触控面积：32 ≥ WCAG 2.5.8 的 24px 下限；底部标签 48 满足移动端常见 44–48 的惯例。不为了「好点」把桌面端控件放到 40+，那会让行与行之间失去紧凑感。

## 5. 实现契约：变量、属性、容器

### 5.1 局部变量（只有别名，没有新色值）

写在原型模块的根选择器上（例如 `.prototypeRoot`）。**全部指向既有变量**，用于给实现者一套好读的名字；不存在第四套色板。

```css
.prototypeRoot {
  /* 线 */
  --proto-line-rule: var(--dsl-g-border);            /* border-l1：分隔 */
  --proto-line-frame: var(--dsl-g-border-strong);    /* border-l2：结构 */
  /* 面 */
  --proto-surface-card: var(--dsw-alias-bg-layer-2, var(--dsl-g-surface));
  --proto-surface-inset: var(--dsw-alias-markdown-code-block, var(--dsl-g-surface));
  --proto-surface-float: var(--dsw-alias-bg-layer-3, var(--dsl-g-surface));
  --proto-fill-placeholder: color-mix(in srgb, var(--dsw-alias-label-primary) 7%, transparent);
  /* 遮罩必须是"两个主题都压暗"，所以用 static 近黑，不用会翻转的 label / 背景色 */
  --proto-scrim: color-mix(in srgb, var(--dsw-static-neutral-bluish-1000) 48%, transparent);
  /* 几何 */
  --proto-pad-x: 24px;
  --proto-radius-page: var(--dsl-g-radius-surface);   /* 12 */
  --proto-radius-control: var(--dsl-g-radius-control); /* 8 */
  --proto-radius-sm: var(--dsl-g-radius-sm);           /* 6 */
  /* 动效：唯一新增的一项，见 §6.6 */
  --proto-dur-pulse: 1.6s;

  container: proto-root / inline-size;
}
```

`color-mix()` 在宿主（Chromium/Electron）可用，现有 `GenuiBlock.module.css` 已在用，不引入新依赖。

### 5.2 状态走 `data-*`，不走 className

**属性名以 catalog / 实现为准**。下表用 `data-variant` 表示导航形态；现有实现（`src/client/blocks/Prototype.module.css`，slice 1）用的是 `data-orientation`。属性名不影响视觉规则，实现沿用既有名字即可，把选择器换掉、规则内容不变。真正要守的是：**状态只走属性，不走 className 组合**。

| 属性 | 取值 | 用于 | 样式消费 |
| --- | --- | --- | --- |
| `data-active` | 布尔（存在即真） | `nav` 当前项、`list-row` 选中 | `[data-active]` |
| `data-disabled` | 布尔 | `list-row`、按钮、`field-group` | `[data-disabled]` |
| `data-invalid` | 布尔 | `field-group` | `[data-invalid]` |
| `data-variant` | `top` / `side` / `tabs` | `nav`（字段 `variant` 同值；`tabs` 即底部标签形态） | `[data-variant="side"]` |
| `data-ratio` | `1:1` / `2:1` / `1:2` | `split` | `[data-ratio="2:1"]` |
| `data-shape` | `circle` | `list-row` 媒体位 | `[data-shape="circle"]` |
| `:hover` / `:active` | 伪类 | 指针反馈、按压 | 不写属性 |
| `:focus-visible` | 伪类 | 键盘焦点 | `outline: 2px solid accent; outline-offset: 2px` |

### 5.3 两级容器查询

布局响应**看容器宽度，不看视口**——原型会出现在会话列、侧栏面板、导出页三个宽度完全不同的地方。

```css
.page { container: proto-page / inline-size; }

@container proto-root (max-width: 600px) {   /* split 可能直接挂在根上 */
  .split { flex-direction: column; }
  .split > * { flex-grow: 0; }
}
@container proto-page (max-width: 600px) {   /* 页内收缩 */
  .page > * { --proto-pad-x: 16px; }         /* 规则不能作用于容器自身，改在子元素上覆盖 */
  .header { gap: 12px; }
}
@container proto-page (max-width: 560px) {   /* 侧栏转横条 */
  .shell { flex-direction: column; }
  .navSide { width: auto; flex: 0 0 auto; flex-direction: row; overflow-x: auto;
             border-right: 0; border-bottom: 1px solid var(--proto-line-rule); }
  .navSide .navGroup { display: none; }
  .navBottom .navItem { height: 48px; }
}
```

两个坑，实现时必须避开（都是本轮实测踩到的）：

1. **容器查询的规则不能作用于容器自身**。写 `@container proto-page { .page { --proto-pad-x: 16px } }` 永远不生效，要在 `.page > *` 上覆盖变量再向下继承。
2. **不在 `page` 里的元素查不到 `proto-page`**。`split` 可能直接挂在根上做「两方案并排」，它必须查 `proto-root`。

## 6. 组件视觉规格

以下 8 个是本轮新增（`page` / `nav` / `list-row` / `field-group` / `empty` / `loading` / `split` / `modal`）。**尺寸单位 px；间距只能取 §4.3 的刻度；颜色只能取 §2/§5 的变量。**

### 6.1 `page` — 页面容器

```
外框   1px dashed 结构线 · 圆角 12 · 底 = 卡片面 · overflow: clip
```

- `overflow: clip` 而不是 `hidden`：`clip` 不产生滚动容器，不破坏内部滚动与焦点环外扩（页面圆角裁切仍生效）。
- 无内边距。内边距由标题栏、区段、行自己承担 —— 这样侧栏的灰面才能贴到外框边上。

**标题栏**

| 项 | 值 |
| --- | --- |
| 内边距 | 上 16 / 左右 `--proto-pad-x`(24) / 下 16 |
| 布局 | `flex; align-items: flex-start; gap: 16` |
| 标题 | 18/24/600 primary |
| 副标题 | 13/20/400 secondary，与标题间距 4 |
| 尾部操作 | `flex: 0 0 auto; gap: 8`，按钮高 32 |
| 无副标题时 | 标题栏高度自然收缩，不补空白 |

窄容器（≤600）：左右内边距 16，`gap` 12。

**状态**：无。`page` 是容器，不承载 hover/active。

**语义**：`<section aria-label="屏 1 · 任务列表">`。

---

### 6.2 `nav` — 导航（三形态）

导航是**示意**不是路由：点击只改视觉选中，不产生跳转（上位 spec 决定）。

**顶栏 `data-variant="top"`**

| 项 | 值 |
| --- | --- |
| 高度 | 48 |
| 内边距 | 0 `--proto-pad-x`(24) |
| 布局 | `flex; align-items: center; gap: 8` |
| 标题 | 13/20/600 |
| 底边 | 1px 分隔线 |
| 溢出 | `overflow-x: auto`，隐藏滚动条（`scrollbar-width: none`）——窄下来横向滚动，不换行、不省略文字 |

**侧栏 `data-variant="side"`**（两种摆放，见 §6.2.1）

| 项 | 并列栏（贴边） | 独立成块（当前唯一形态） |
| --- | --- | --- |
| 宽度 | 200（`flex: 0 0 200px`） | 200（`max-width: 100%`） |
| 外边距 | 0 | 上 16 / 左右 `--proto-pad-x` |
| 圆角 | 0 | 8 |
| 描边 | 右边 1px 分隔线 | 四边 1px 分隔线 |
| 底 / 内边距 | 内嵌面 / 8 | 内嵌面 / 8 |
| 方位 | 纵向 flex，项间距 4 | 同左 |
| 分组标题 | 12/18/400 secondary，内边距 8 8 4 | 同左 |

**底部标签 `data-variant="tabs"`**（字段值就是 `tabs`）

| 项 | 值 |
| --- | --- |
| 项高 | 52（窄容器 48） |
| 布局 | `flex: 1 1 0`，纵向，图标 20 + 标签，间距 4 |
| 顶边 | 1px 分隔线 |
| 圆角 | 0（贴边） |

**导航项（三形态共用）**

| 状态 | 表现 |
| --- | --- |
| 默认 | 高 32 / 左右内边距 8 / 圆角 8 / 13/20/500 secondary / 图标 16 / 图标与文字间距 8 |
| hover | 底 = `--dsl-g-hover` |
| 当前项（顶栏/侧栏） | 底 = `--dsl-g-hover`（侧栏用卡片面 `--proto-surface-card`，因为底是灰面）+ 文字 primary |
| 当前项（底部） | 文字 primary + **图标** accent；底透明 |
| disabled | 文字 `label-dimmed`，无 hover |

**为什么当前项不用 accent 文字色**：accent 在浅色只有 4.23:1，13px 文字不达 4.5:1；而图标属于非文本图形，3:1 即可。所以「颜色」只上图标，「选中」靠面与字重，两条通道分开。侧栏在灰面上抬一档（卡片面）比加边框更干净。

**窄容器（≤560，侧栏）**：**只换方向，不换形态** —— `flex-direction: row`、`overflow-x: auto`、宽度 `auto`、隐藏分组标题，项仍 32 高；描边跟随该形态的定义（并列栏的右边线换成底边线，独立块的四边框与圆角保持不变）。**不隐藏任何导航项**——隐藏会让人误判信息架构。

#### 6.2.1 侧栏摆放：列还是块

同一个 `variant="side"` 有两种合法摆放，区别只在「有没有内容并排」：

| | 并列栏 | 独立成块 |
| --- | --- | --- |
| 何时 | 与内容并排（未来的 shell，或 `split` 里的一栏） | 页内只有导航，或导航直接挂在原型根上（**当前实现只有这一种**） |
| 形态 | 贴边、无圆角、右边一条线 | 缩进 `--proto-pad-x`、圆角 8、四边框 |
| 右侧留白 | 内容自己的 `--proto-pad-x` | `--proto-pad-x`（与页面标题左边缘对齐） |

**右侧留白就取 `--proto-pad-x`（24 / 窄 16），不是任意值。** 独立成块时块的左右外边距都取它，于是块的左边缘与页面标题对齐、右边缘与标题右端对齐；块内右内边距固定 8（与项的左内边距一致），所以「项右端到块边」也是 8。

「右侧留白没定」的典型症状就是：块只有左边缩进、右边一路悬空到外框，读起来像半截面板。

**为什么独立成块必须有描边**：内嵌面在浅色下只有 1.05:1，独立成块时没有贴边的位置参照，不描边就只剩几行文字浮在白底上。并排栏不需要描边，因为它一侧贴着外框、另一侧紧邻内容，位置已经定义了边界。

### 6.3 `list-row` — 紧凑列表行

| 项 | 值 |
| --- | --- |
| 布局 | `flex; align-items: center; gap: 12` |
| 最小高 | 56（有副文本）/ 40（只有主文本） |
| 内边距 | 上下 8 / 左右 `--proto-pad-x` |
| 分隔 | 相邻行**顶部** 1px 分隔线；首行不画 |
| 媒体位 | 40×40 / 圆角 8 / 灰块（`data-shape="circle"` 时 999，用于头像） |
| 内容列 | `flex: 1 1 auto; min-width: 0` |
| 主文本 | 14/20/400 primary，单行省略 |
| 副文本 | 13/18/400 secondary，上间距 4，单行省略 |
| 尾部 | `flex: 0 0 auto; gap: 8`，12/18/400 secondary |
| 尾部图标 | 16，`label-caption` |

| 状态 | 表现 |
| --- | --- |
| hover | 底 = `--dsl-g-hover` |
| 选中 `data-active` | 底 = `--dsl-g-hover`（不加边框、不加左侧色块） |
| disabled | 文字 `label-dimmed`，`cursor: not-allowed`，**不显示 hover 底** |

**不用整体 `opacity` 表达 disabled**：透明度会把分隔线一起淡掉，行与行之间的结构消失。

**窄容器（≤480，可选实现）**：左右内边距降为 12（若 `--proto-pad-x` 已是 16 则不再降），主/副文本维持单行省略，**尾部元素不隐藏**，允许 `flex-wrap` 换到第二行右对齐。任何「窄了就藏操作」的做法都不接受 —— 隐藏会让人以为那个操作不存在。

**语义**：整行是一个可点目标时用 `<button>`（或 `<a>`），媒体位 `aria-hidden`，行的可访问名由主文本 + 副文本合并（`aria-label` 或内联文本自然合并）。

### 6.4 `field-group` — 字段组

| 项 | 值 |
| --- | --- |
| 布局 | `flex; flex-direction: column` |
| 标签 | 13/20/500 primary，下间距 8 |
| 控件 | 高 32 / 左右内边距 8 / 圆角 8 / **1px 结构线**描边 / 13/20 |
| 提示 | 12/18/400 secondary，上间距 4 |
| 多字段间距 | 16 |

| 状态 | 表现 |
| --- | --- |
| 默认 | 描边 = 结构线（`border-l2`），底透明 |
| hover | 不加深描边（避免与「已选中」混淆）；保持 |
| focus | `outline: 2px accent; offset: 2`，描边不变 |
| invalid `data-invalid` | 描边 = `state-error-primary`；提示文字换 `state-error-primary`；`role="alert"` |
| disabled `data-disabled` | 底 = 内嵌面；描边 = 分隔线；文字 `label-tertiary`；标签 `label-dimmed`；`cursor: not-allowed` |

> `label-tertiary` 在这里是 §4.1「可读 12px 文本不用 tertiary」的唯一豁免：WCAG 1.4.3 明确把不可用控件排除在对比度要求之外。

**控件描边必须用 `border-l2` 而不是 `border-l1`**：l1（浅 4%）在白底上几乎不可见，输入框会变成「没有边的输入区」，读起来像纯文本。这条与 §2.2 一致：控件属于「结构线」。

**invalid 靠三条通道冗余**：红描边 + 红文案 + `role="alert"`。不靠图标与否都行，但**不能只靠颜色**。

**窄容器**：不变形；控件保持 `width: 100%`。

**语义**：`<label for>` 关联控件；错误用 `aria-describedby` 指向错误文本节点。

### 6.5 `empty` — 空态

垂直节奏（从上到下）：`24` 内边距 → 图形位 40×40 → **12** → 标题 → **8** → 说明 → **16** → 操作 → `24` 内边距。

| 项 | 值 |
| --- | --- |
| 布局 | `flex; column; align-items: center; text-align: center` |
| 内边距 | 上下 24 / 左右 `--proto-pad-x` |
| 图形位（可省） | 40×40 / 圆角 8 / **灰块**（不是虚线框）/ 与标题间距 12 |
| 标题 | 14/20/500 primary |
| 说明 | 13/20/400 secondary，与标题间距 8 |
| 操作 | 按钮高 32，与说明间距 16 |
| 居中 | 只在这里允许整块居中（§4.2） |

实现上可以用 `gap: 8` + 图形位 `margin-bottom: 4` + 按钮 `margin-top: 8` 得到表里的 12 / 8 / 16。

图形位若来自真实图标库（Lucide），用图标而不是灰块；灰块只在「以后放插画」时用。

**为什么不做虚线（可引用的四条依据）**

1. 虚线在本文的定义是「这块不是真实界面的一部分 / 结构还没定」（§2.3）。`empty` 与 `loading` 都是**生产里真实会出现**的状态，讨论它们的目的恰恰是确定「没数据、加载中长什么样」。
2. 虚线会让评审把「已经设计好的状态」误判成「还没设计」，于是跳过对它的评审——这正是低保真最贵的失效模式（§0.1 的第 2、3 条）。
3. 这两个状态的语义靠**文案 + 灰块 + 属性**（`aria-busy`、`role="status"`、`role="alert"`）表达，不需要边界信号。
4. 反证：`empty` 画成虚线框，用户会问「这里要画什么插画？」；`loading` 画成虚线框，用户会问「骨架还没做完？」——讨论都会被带离状态本身。

> 给评审的一句话：**虚线标的是「未定」，不是「简陋」。**

---

### 6.6 `loading` — 加载态

骨架的节奏由三件事决定：行高、行距、宽度错落。

| 项 | 值 |
| --- | --- |
| 文本条 | 高 12 / 圆角 6 / 底 = 灰块色 |
| 行距（同块内相邻文本条） | 8 |
| 块骨架 | 文本条纵向排列，间距 8；块内边距 16 / `--proto-pad-x` |
| 行骨架 | 媒体 40×40 圆角 8 + 文本条 2 根；媒体与文本间距 12；文本条间距 8；行内边距 8 / `--proto-pad-x` |
| 宽度档 | 只用 100 / 88 / 76 / 72 / 56（%），不出现其它百分比 |
| 每块条数 | ≤ 3 条 |
| 动效 | 透明度 1 → 0.55 → 1，周期 1.6s，`ease-out`，无限 |
| 减动效 | `prefers-reduced-motion: reduce` 下**完全静止**（不是放慢） |

**错落规则**：相邻两条不能等宽——等宽会让块收出一条整齐的直边，看起来像实心矩形，不像文字。

| 条数 | 推荐序列 | 说明 |
| --- | --- | --- |
| 1 | 100 或 88 | 不要用 56，太短会读成「一个小标签」 |
| 2 | 100 · 72 | 收口在 72 |
| 3 | 100 · 88 · 72 | 逐级收口；不要 100 · 72 · 100（中间凹进去） |

行骨架里的两条固定用 88 · 72（或 100 · 76）；两行时不用 56——56 会让整行看起来只有一半内容。

**为什么脉冲用新时长 1.6s**：既有 `--dsl-g-dur-*` 是 0.15 / 0.45 / 0.6，都属「一次性的反馈或入场」，没有一个适合「持续呼吸」。这是本文唯一新增的时长，命名 `--proto-dur-pulse`，写在原型模块根，不动 `GenuiBlock.module.css`。

**语义**：容器 `aria-busy="true"` + `role="status"`，骨架节点 `aria-hidden="true"`。

---

### 6.7 `split` — 双栏

| 项 | 值 |
| --- | --- |
| 布局 | `flex; gap: 16; align-items: stretch` |
| 栏 | `flex: 1 1 0; min-width: 0` |
| 比例档位 | `1:1`（默认）/ `2:1` / `1:2`，**只此三档** |
| 并排时 | 两栏**等高**（栏内 `page` 撑满） |
| 断点 | 容器 ≤600 堆叠（与 page 内边距收缩同一阈值） |
| 堆叠后 | `flex-direction: column`、`gap` 仍 16、栏 `flex-grow: 0`、每栏满宽 |
| 分隔线 | 默认**不画**；`data-divider="true"` 时两栏之间 1px 结构线 |

**为什么只开放三档比例**：没有拖拽，任意比例（3:2、4:3）会让文字换行随容器宽度漂移，讨论时说不清「这里为什么断了」。三档覆盖两种真实需求：对半比较（`1:1`）与主次（`2:1` / `1:2`）。

**分隔线（可选，默认关闭）**

| 项 | 值 |
| --- | --- |
| 默认 | 不画。两栏各有 `page` 外框时，竖线会成为第三条线，读起来像三栏 |
| 启用 | `data-divider="true"`：`border-left: 1px solid` **结构线（l2）** 画在第二栏左侧，第二栏 `padding-left: 16` 承担间距 |
| 为什么用 l2 不用 l1 | 实测：4% 的短竖线在白底上等于不可见（1.09:1）。分隔线不能是「看不见的线」 |
| 主题 | 颜色由 token 翻转，没有主题分支 |
| 堆叠后 | 线移除，恢复 16 间距——否则会留一条悬空的横线 |

`split` **自身不铺面、不加内边距**，除上表的分隔线选项外也不画线。它只负责比例与间距；边界由各栏里的 `page` 自己带。

### 6.8 `modal` — 确认层与底部面板

两个形态，`variant` 取 `dialog` / `sheet`。

**层级与定位**

| 项 | 值 |
| --- | --- |
| 浮层 | `position: absolute; inset: 0; z-index: 10`，相对 `page` |
| `page` | `position: relative; z-index: 0` |
| 角标 | `z-index: 2`（必须高于 page，否则浮层一出现就被压住——实测） |
| 禁止 | `position: fixed`：会逃出页面框、盖住对话；并排比较两屏时互相覆盖 |
| 遮罩范围 | 只覆盖 `page` 外框内，圆角由 `page` 的 `overflow: clip` 裁出 |

**遮罩**

| 项 | 值 |
| --- | --- |
| 颜色 | `--proto-scrim: color-mix(in srgb, var(--dsw-static-neutral-bluish-1000) 48%, transparent)` |
| 为什么用 static 近黑 | 遮罩必须两个主题都「压暗」。`label-primary` 在深色主题下是近白，拿它做遮罩会变成提亮，方向反了；`bg-base` 在浅色是白，会变成冲淡而不是压暗 |
| 为什么是 48% | 浅色白底叠上去约 `#8d8d8e`：背景退到「可辨但不再抢注意力」。低于 40% 背景文字仍抢眼，高于 60% 深色主题里弹层边界消失 |
| 主题 | 无分支（static token 本就不随主题翻转） |

**面板**

| 项 | dialog | sheet |
| --- | --- | --- |
| 宽度 | `min(360px, 100%)` | 100% |
| 位置 | 居中（`align-items: center`） | 贴底（`align-items: flex-end`） |
| 圆角 | 12 | 12 12 0 0 |
| 面 | `--proto-surface-float`（bg-layer-3） | 同左 |
| 边 | **无描边** | 无描边 |
| 阴影 | `--dsl-g-shadow-float` | 同左 |
| 内边距 | 24 | 16 顶 / `--proto-pad-x` 左右 / 24 底 |
| 标题 | 15/22/600 primary | 同左 |
| 正文 | 13/20/400 primary，标题下间距 8 | 同左 |
| 操作区 | 右对齐，`gap: 8`，按钮高 32，上间距 16 | 同左（按钮不堆叠） |

**为什么浮层没有描边**：DESIGN.md §3.1 的规则是「描边与阴影永不叠加」。浮层是唯一允许阴影的层级，边界由「遮罩对比 + 阴影」定义；再加 1px 边会让它在浅色下读成一张普通卡片。

**按钮层级**

| 操作 | 样式 |
| --- | --- |
| 主操作 | 灰底 + 600 字重（与页面内主操作一致，不用品牌色实心） |
| 次操作 | **描边按钮**，不用文字按钮——草图里无边界的文字会读成链接 |
| 危险操作 | 描边与文字都取 `state-error-primary`，600 字重；深色下 4.24:1 略低于 4.5，靠文案兜底（§7.2） |

**焦点**

| 项 | 值 |
| --- | --- |
| 焦点环 | `outline: 2px solid var(--dsl-g-accent); outline-offset: 2px`，只在 `:focus-visible` 出现 |
| 打开时 | 焦点移入浮层（首个可聚焦元素），但**不显示焦点环**——自动聚焦不是键盘导航 |
| 关闭后 | 焦点归还触发元素（行为归码匠，视觉上不加额外标记） |

**动效**

| 项 | 值 |
| --- | --- |
| 遮罩 | 不透明度 0 → 1 |
| dialog | 不透明度 0 → 1，同时 `translateY(4px)` → 0 |
| sheet | `translateY(100%)` → 0 |
| 时长 / 曲线 | `var(--dsl-g-dur-fast)`（0.15s）+ `var(--dsl-g-ease-out)`，进出同参数、不新增时长 |
| 不做 | 缩放（scale）、旋转、遮罩模糊、弹簧曲线 |
| reduced-motion | `transition: none; animation: none` —— 直接出现与消失。不放慢、不保留淡入 |

**窄容器：不自动转形态**

`dialog` 与 `sheet` 是**两个可选方案**，不是同一个东西的两档，所以窄容器下不互换：

| 形态 | 容器 ≤600 |
| --- | --- |
| dialog | 宽度自然收缩到 `min(360px, 100%)`，内边距 24 → 16，**仍居中**、圆角仍 12 |
| sheet | 不变（本就满宽），左右内边距跟随 `--proto-pad-x` |

判断原则（与 §6.2 的侧栏转换对照）：**自动转换只用于「原形态在容器里放不下」**（侧栏在 390 宽度下无法成立 → 转横向）；**不用于「这是两个方案」**（dialog 在窄屏照样能居中显示，只是不够舒展，而「够不够舒展」正是要讨论的东西）。要比较两种形态，就用 `split` 并排两个 `page`，各带自己的浮层。

**语义**：`role="dialog"` + `aria-modal="true"` + `aria-labelledby` 指向标题；背景 `inert`；Escape 关闭；关闭后焦点归还（行为契约在上位 spec，不在本文）。

深浅切换的唯一开关是宿主的 `body[data-ds-dark-theme]`。**新代码里不写任何主题分支**——所有分支都已在 token 层完成。若某处真的需要分主题，只允许在 token 层加，不在组件规则里写 `body[data-ds-dark-theme] .x`。

### 7.2 对比度实测（浅色 / 深色，文本 vs 所在面）

| 组合 | 浅色 | 深色 | 判定 |
| --- | --- | --- | --- |
| label-primary / 卡片面 | 18.90:1 | 13.34:1 | ✓ |
| label-secondary / 卡片面 | 5.80:1 | 9.25:1 | ✓（12px 可用） |
| label-tertiary / 卡片面 | **3.71:1** | 6.53:1 | 浅色 ✗ 不可用于可读文本 |
| label-caption / 卡片面 | **2.13:1** | 3.76:1 | ✗ 仅装饰 |
| accent / 卡片面 | **4.23:1** | 5.99:1 | 浅色 ✗ 文字，✓ 图标 |
| error-primary / 卡片面 | 4.50:1 | **4.24:1** | 临界 / 深色 ✗ 略低 |
| 结构线 / 卡片面 | 1.25:1 | 1.46:1 | 低于 1.4.11 的 3:1（宿主语言取舍） |
| 灰块 / 卡片面 | 1.16:1 | 1.23:1 | 纹理信号，非信息通道 |

由此得到三条硬规则（已写进 §4.1）：

1. **可读的 12px 辅助文本一律 `label-secondary`**，不用 `label-tertiary`（浅色 3.71:1）。`label-tertiary` 只给占位字符。
2. **accent 不给文字上色**，只给图标与焦点环（浅色 4.23:1 不达文本线，但过 3:1 图形线）。
3. **错误信息必须多通道**（描边 + 文本 + `role="alert"`），因为深色下错误文本 4.24:1 略低于 4.5:1，不能只靠颜色传达。

### 8.3 没验证到的（写在交付里，别当成已确认）

- **组件实现未验证**：`page` / `nav` / `list-row` / `field-group` 已落地（切片 1），`modal` / `split` / `empty` / `loading` 尚未写进 `src/client/`。布局 bug 只会在真实组件里出现（例如 `overflow: clip` 与 `modal` 的焦点陷阱共存、`position: absolute` 与流式追加重渲染）。
- **遮罩用的是 static 近黑**：`--dsw-static-neutral-bluish-1000` 不随主题翻转，这是刻意的；但若宿主后续换静态色板或做高对比主题，48% 需要复验。48% 本身是按对比度与观感定的，没有做用户测试。

- **虚线 dash 节奏跨平台未测**：只测了 Chromium。
- **`border-l3/l4` 未使用**：recon 提到宿主有 l3/l4，但我们没有它们的取值。若后续确认，控件描边可考虑升到 l3 以满足 1.4.11 的 3:1；现在不猜。
- **肤色插件未装**：若以后装上会改写 `--dsw-alias-*`，本规范全部派生，理论上会跟着变；但灰块色（label 7%）与虚线在极端配色下需复验。

### 8.4 验收判据（三条，可对照检查）

**判据 1 · 两层分开看都成立**

**判据 2 · 线面清点**

### 9.1 切片 1 差异（已合入，保留作回溯）
