# Spec：对话内低保真交互原型通道（Prototype Channel）

> 状态：ready-for-agent
> 日期：2026-11-21
> 关联调研：`docs/research/prototype-channel.md`（外部实现对照）、`docs/research/component-library-reuse.md`（组件库复用与许可）
> 设计基线：`plugins/vt-gen-ui/DESIGN.md`、`plugins/vt-gen-ui/AGENTS.md`
> 视觉规则（本轮新增组件的取值与验收）：`docs/specs/prototype-visual-rules.md`

## Problem Statement

在对话里讨论界面方案时，用户只能得到文字描述或数据型组件的结果。现有 50 个组件是为「把数据说清楚」设计的——表格、指标、图表、表单控件——但缺页面级结构：没有页面容器与标题栏、没有导航、没有「头像 + 主副文本 + 尾部操作」的紧凑列表行、没有弹层。

后果有三个。第一，让 Agent 描述一个「列表页点进去是详情页」的界面，它只能用卡片套卡片硬堆，出来是仪表盘的味道，不是界面原型，双方对结构的理解对不齐。第二，用户无法在对话里「点着看」：想看第二屏长什么样，只能让模型重画一版，一步一轮回复，讨论节奏被打断。第三，确认了结构之后，没有一条干净的交接路径把结论交给高保真设计环节，全靠口头复述。

现有替代方案都不合适：另开一个原型工具，等于把讨论从对话里搬走；用沙箱 iframe 跑任意 HTML（Visualize、Claude Artifacts 那条路），表达力够但引入了任意脚本的信任面，且官方自己也把自由度收回到受控结构（Claude 2026-09-16 起停止新建自由 HTML artifact，OpenAI 把「能真跑流程」分流给托管运行时）。我们不需要可运行的应用，需要的是一张能一起讨论的、可以点的结构稿。

## Solution

给 `dsh-ui` 通道增加一组**页面级原型组件**和一层**屏幕状态机**，让模型一次输出多屏低保真原型：用户在对话里点击切屏、勾选、调滑块，状态与跳转全部在浏览器内完成，零模型往返；确认之后，把这一版作为锚点交给设计环节出高保真稿。

视觉上采用「简洁的线面风格」（参考 Notion）：以 1px 线与浅灰面建立层级，不用重阴影、不用渐变、不用装饰性插画。保真度按层划分——**内容与外观层低保真，排版与节奏层高保真**：虚线框、灰阶填充、区域角标给出「这是草图」的信号；字号、行高、间距、对齐按最终品质做。依据是低保真与高保真在「发现结构性问题」上等效（Walker 2002）、低保真能降低设计者沉没成本依恋并让评审者更敢提意见（NN/g 2016），而低保真会被高估美感、不能用于评视觉质量（Sauer 2009）。

组件字段与 DOM 语义借用 `shadcn/ui` 的 Field / Item 两个族（MIT，源码分发），不引入它的运行时；提示词契约借用 `json-render` 的「catalog 单源产出提示词」模式（Apache-2.0），消除「SKILL.md 手写字段表」与「渲染器校验 schema」两份真相长期错位的问题。

## User Stories

1. 作为正在和 Agent 讨论页面结构的用户，我想要 Agent 直接给出可点的低保真界面而不是文字描述，这样我能一眼看懂它理解的结构对不对。
2. 作为用户，我想要一屏以内看到「两个方案并排」，这样我能在同一处比较信息层级而不是来回翻消息。
3. 作为用户，我想要点击原型里的按钮就切到下一屏，而不是让模型重画一版，这样讨论能连续进行。
4. 作为用户，我想要在原型里返回上一屏，这样我能反复比较两条路径。
5. 作为用户，我想要切屏时不丢已经填过的选择与滑块值，这样我能验证「先选后跳」的流程。
6. 作为用户，我想要在原型里勾选、单选、拖动滑块，并且这些操作立刻就生效，这样我不用等一轮模型回复。
7. 作为用户，我想要原型不自动把每次点击都变成一条新消息，这样对话历史不会被交互噪音填满。
8. 作为用户，我想要在一次讨论结束时说一句「就这个」，由 Agent 把当前状态（选了哪屏、填了什么）作为结论接收，这样确认动作只有一次。
9. 作为用户，我想要原型在小窗口里也能看，窄到手机宽度时双栏自动堆叠，这样我不必放大页面。
10. 作为用户，我想要原型在浅色和深色主题下都成立，这样它跟我当前的界面是一体的。
11. 作为使用键盘的用户，我想要能用 Tab 走到导航与主要操作、用 Enter 触发切屏，这样我不被迫用鼠标。
12. 作为使用读屏的用户，我想要列表行、字段组、弹层有正确的角色与名称，这样我能听懂这一屏的结构。
13. 作为对动画敏感的用户，我想要系统开启「减少动态效果」时切屏不做动画，这样不会不适。
14. 作为用户，我想要原型能表达「空态」与「加载中」，这样我能讨论数据没来时的界面。
15. 作为用户，我想要原型能弹出确认层或底部面板，这样我能讨论「这一步要不要二次确认」。
16. 作为用户，我想要原型里出现「页面标题 + 主操作按钮 + 内容区」这种完整骨架，这样我讨论的是页面而不是卡片。
17. 作为用户，我想要原型里的导航有顶栏、侧栏、底部标签三种形态可选，这样桌面和移动两套方案都能表达。
18. 作为用户，我想要在模型输出一半时就能看到已完成的组件，这样长原型不用等全部生成。
19. 作为用户，我想要某个组件字段写错时其余部分照常渲染并给出可读提示，这样一个笔误不会毁掉整屏。
20. 作为用户，我想要原型能导出成单文件 HTML，这样我能把它发给不在对话里的人看。
21. 作为设计负责人，我想要低保真稿明确「这不是视觉稿」，这样评审时不会被追问「什么时候上线」。
22. 作为设计负责人，我想要确认后的原型能带着结构结论交接给高保真环节，这样不用重新描述一遍布局。
23. 作为现有用户，我想要原来的表格、指标、图表用法完全不变，这样这次新增不影响我已有的会话与习惯。
24. 作为插件维护者，我想要新组件的字段定义只有一个来源，这样提示词和校验不会各说各话。
25. 作为插件维护者，我想要新增是纯加法——现有 50 个组件名与必填字段一个都不动，这样历史会话与已缓存的技能手册不会失效。

## Implementation Decisions

**组件族（8 个新类型，纯加法）**

- `page`：页面容器，含可选标题栏（标题、副标题、尾部操作区）与内容区；是原型的根节点，窄容器下内边距自动收紧。
- `nav`：导航，`variant` 取顶栏 / 侧栏 / 底部标签三形态；当前项用 `active` 标记。聊天正文里导航是**示意**不是功能：点击只做视觉选中，不承载路由。
- `list-row`：紧凑列表行，媒体位 + 主文本 + 副文本 + 尾部操作；借 `shadcn/ui` Item 的零件划分（媒体 / 内容 / 标题 / 描述 / 操作 / 头 / 脚）。
- `field-group`：字段组，标签 + 控件 + 提示 + 错误；借 `shadcn/ui` Field 的零件划分（组 / 标签 / 描述 / 错误），错误态走 `role="alert"`。
- `modal`：确认层与底部面板两形态，含标题、内容、操作区；行为必须包含焦点陷阱、背景 `inert`、滚动锁、Escape 关闭、关闭后焦点归还。
- `empty`：空态，图形位（可省）+ 标题 + 说明 + 可选操作。
- `loading`：加载态，骨架行或骨架块，`lines` 控制行数。
- `split`：双栏布局，`ratio` 取静态比例（不提供拖拽），容器窄于阈值时自动堆叠为单列。

现有 50 个 `type` 的名字、必填字段名、`action` payload 形状一律不改；新增只做加法。围栏标签仍为 `dsh-ui`。

**屏幕状态机**

一个 spec 可包含多屏：`screens` 为屏 id 到组件树的映射，`initial` 指定起始屏；节点可声明 `goto` 指向另一屏。状态机在客户端运行，切屏不产生消息、不请求模型。屏幕栈支持返回上一屏。状态（当前屏 + 表单值 + 滑块值）按「会话 + 内容指纹」持久化，内容变化即重置，沿用现有交互状态的持久化约定。

**状态进 DOM 属性**

交互与视觉状态统一以 `data-*` 属性表达（如 `data-state`、`data-invalid`、`data-orientation`、`data-active`），样式层用属性选择器消费。这样组件不靠传递 `className` 组合状态，视觉规则与逻辑解耦。

**提示词单源**

组件定义收敛为一份 catalog：由它同时产出「模型看的系统提示词片段」「围栏校验用的 schema」「渲染注册表」。系统提示词里的组件清单、字段速查、易错字段由 catalog 生成，不再手写维护；`SKILL.md` 保留为编排指南（何时用哪类组件、范例、坑），其中涉及字段的部分改为引用生成的清单。生成结果必须可直接替换现有提示词段落中的对应片段。

**复用边界**

- 不引入 Tailwind、Radix、Base UI 等运行时依赖；样式仍是自研 CSS Modules，颜色只来自宿主 `--dsw-alias-*` / `--dsw-static-*`，不写死 HEX。
- 只借 `shadcn/ui` 的零件划分、可访问性语义与状态命名；DOM 与样式全部重写。
- 只借 `json-render` 的 catalog → prompt 模式与 `root + elements` 的扁平引用式结构（扁平结构对流式追加友好、引用可校验）；**不引入**它的 `$state` / `$cond` / `$computed` / `watch` / `setState`，保持「无任意表达式、无任意 JS」这条边界。
- 界面动效保留 `prefers-reduced-motion` 分支。

**失败与降级**

单组件字段错误仍走现有容错：能救则救并给 `warning`，救不了则丢弃该组件、其余照常渲染；整块不可渲染才退回代码块。屏幕状态机不可用时（如旧版渲染器缓存）退化为只渲染 `initial` 屏。

**交接**

确认态下，把「当前屏 + 已选值 + 屏幕路径」序列化为可读结论随消息发出；导出沿用现有单文件 HTML 通道，导出内容包含屏幕状态机，离线可点。

## Testing Decisions

**测试边界（唯一 seam）**

以 catalog 为最高 seam：它是「组件定义」的唯一来源，下游三件产物（系统提示词、校验 schema、渲染注册表）都从它派生。测试只打这个 seam 的两端——catalog 的输入，和对外可观察的产物与渲染结果；不在组件内部实现细节上打桩。这一条 seam 同时覆盖「提示词与校验不一致」这类回归，避免为每个组件各开一个测试缝。

**什么算好测试**

只断言外部行为：给定一段 spec（或一段模型输出），断言渲染出的 DOM 语义与可观察状态（角色、可访问名称、`data-*` 状态、点击后当前屏切换、窄容器下是否堆叠、减少动效时是否有动画类），以及 catalog 派生出的提示词是否包含必需字段与禁止项。不断言类名 hash、内部函数调用次数、组件内部结构。

**需要覆盖的模块**

- catalog 派生：提示词片段与校验 schema 对同一批组件定义保持一致；新增组件自动出现在两者里。
- 校验与容错：未知 `type`、缺必填、错字段名分别落到「救 / 丢 / 降级」三档。
- 屏幕状态机：初始屏、`goto` 切屏、返回、状态在切屏后保留、内容指纹变化后重置。
- 组件渲染与可访问性：`field-group` 的错误关联、`modal` 的焦点陷阱与 Escape、`nav` 的当前项语义、`list-row` 的名称合并、`split` 的窄容器堆叠。
- 降级：状态机不可用时只渲染 `initial` 屏。

**现有基础与缺口**

仓库目前没有测试基建，只有 `typecheck` 与 `build` 两条脚本。需要先引入一个最小测试运行器（建议 vitest + jsdom），并把 `test` 脚本接入现有检查流程；不为视觉细节写快照测试，视觉验收仍走现有的截图脚本（浅色 / 深色各一张）作为人工基线。

## Out of Scope

- 沙箱 iframe 与任意 HTML/JS（B 形态），以及配套的 CSP、postMessage 桥。
- 静默回传（`ui/update-model-context` 那档语义）；本轮仍用显式 action 与一次性确认。
- 真实数据绑定、后端调用、路由与多页应用。
- 高保真视觉、与设计环节的自动交接（本轮只保证结构结论可读、可导出）。
- 拖拽式分栏、自定义表达式、条件显示等「有状态应用」能力。
- 现有 50 个组件的视觉重做（另立任务）。

## Further Notes

- 风格参考：Notion 的线面语言——1px 线、浅灰面、克制的圆角、无重阴影。低保真信号靠虚线边界与灰阶块，不靠手绘质感。
- 用户已明确：低保真原型的设计风格采用简洁线面风格，参考 Notion；高保真环节由设计 Bot 承接。
- 外部证据与许可边界见两份 `docs/research/` 文档；其中 `tldraw`（禁生产使用）、`Tailwind Plus` / `Flowbite Pro`（禁止再分发与做 UI 库）、`Preline`（MIT + Fair Use 附加条款）**不可用于本项目**。
- 关于「低保真不能评视觉质量」这条，要写进交付说明，避免评审时被当作视觉稿讨论。
