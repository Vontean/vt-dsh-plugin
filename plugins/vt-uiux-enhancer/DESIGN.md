# DESIGN — dsh-vt-uiux-enhancer

这份文档只回答**设计**问题：要什么观感、否掉过什么、跨补丁的取舍是什么。
实施细节（补丁类型怎么选、会踩什么坑、Harness 内部机制）在 `DEVELOPMENT.md`。
具体取值与补丁清单在 `client.js`；本文只在「这个值为什么是它」属于设计判断时才引用数值。

## 目标与边界

- 让 Harness 读起来像一份**干净的白纸界面**：纯白画布、暖调中性文字、极浅的边界。
- **默认只做外观**：颜色、圆角形状、阴影、间距、对齐、字重；不改布局结构、不改交互逻辑、不加功能。
- 越界只有**三处**，共同前提是三条同时成立 —— 内容没有消失（双向可回）、
  没有新增持久状态、关掉插件后原样回来：
  1. **用入口换空间**：某个低频功能占着常驻空间时，把它的常驻入口收进已有的信息行、把空间还给内容。
     目前只有「视图切换入口」走这条路。
  2. **用披露换密度**：内容本身没有变，只是默认不一次性铺满。超长用户消息折叠成 20 行，
     保留「展开」把全文原位放回来。这一条不是"美化"，是"读得下去"：一条 60 行的粘贴内容会把
     后面所有轮次推出屏幕，滚动本身就成了任务。
  3. **接管阅读位置**：流式回答不再把读者正在读的段落推出屏幕。唯一一处改到「应用的行为」
     而不是外观 —— 但同样是可逆的：只在回答期间限位滚动写入，释放即恢复。
- **必须可完全撤销**：插件关闭后 Harness 精确回到出厂外观。因此不写死任何 Harness 文件，也不留下
  常驻的定时器、监听器或网络请求。

## 视觉方向

三条取舍，都是被否过的方案换来的：

1. **画布纯白，暖只在文字与侧栏**。
   否掉「米黄画布 + 纯白浮起面」：白面在黄底的互补对比下显冷紫，整体发脏。
   推论一：不要在画布与浮起面之间制造冷暖嵌套对比。
   推论二：**填充档一律中性**。hover、选中行、次级按钮这类浅底一旦带暖就显脏 —— 设置页的选中行
   曾因此偏红灰（参考色阶 100 当时是 `#f1ede8`，R−B = 9）。暖只留给文字（500 以上）与侧栏底色。
2. **边界用浅，深浅靠文字层级**。
   否掉「细硬描边 + 低透明度灰雾」表达浮起：读起来像贴纸，脏。
   推论：浮起用「有方向的阴影 + 一条可辨的细边」表达，不用均匀光晕。
3. **控件形状成体系**：同一类控件只有一个尺寸与形状，容器内保持光学等距。
   否掉「逐处微调」：同类控件尺寸/形状不一致时，任何单点修饰都显得随意。
4. **动效必须承载信息**：动画只表达「状态正在变」，且变化本身要能被读出来。
   轮次跳转条是这条原则的样板：静止时全是短刻度，靠近指针才长出来，邻居逐级回落 ——
   长度就是「你在第几轮」，移动过程本身就是反馈。
   否掉「静止时用三档长度区分当前/悬停」：20px 与 18px 只差 2px，读不出来，只留下噪声。

参照物是本机 Codex 桌面端（`ChatGPT.app`）。取值比对与实测数据在需要时现读，不写进本文。

## 跨补丁决策记录

单点理由写在对应补丁的注释里；这里只记影响多个补丁的判断。

| 决策 | 选择 | 依据 |
|---|---|---|
| 配色层级 | 纯白画布 + 中性填充 + 暖灰文字 + 侧栏暖白 | 见「视觉方向」1 |
| composer 阴影 | Codex 配方：`1px 4%` 描边 + 近影贴地 + 大模糊方向性远影 | 脏不脏取决于**有没有方向和起点**，不是模糊半径 |
| 浮层面板 | 近不透明纯白 + `blur(8px)` + 实体细边 + 聚拢阴影 | 见 `DEVELOPMENT.md` 陷阱 7 |
| 中文控件字重 | 比同排拉丁文字低一档（500→400） | 13px 下中文墨迹填到 11px，拉丁小写只填 7px；同字重会让中文显粗 |
| 圆形控件 | 图标按钮统一 28px 正圆，与发送按钮同尺寸 | 见视觉方向 3；28px 是那一排的既有尺寸 |
| 原生 tooltip | 输入框内改为自绘气泡，沿用应用的 tooltip token 与几何 | 系统灰框与设计系统无关，且与旁边的 `<Tooltip>` 并排出现两种外观 |
| 轮次跳转条 | 移到会话区左侧、贴住侧边栏；静止 6px 刻度，悬停涨到 26px，邻居逐级回落 | 位置该由**长度**表达（一根跟随指针的扫描线）；原来挂在右侧外沿，且三档长度只差 2px，读不出当前位置 |
| 会话边缘 | 上下各 24px 渐隐，只在该方向确实还有隐藏内容时出现 | 硬截断等于把一行字剪断；轨迹视图与应用的滚动面板本来就用 24px 渐隐，消息视窗是唯一的例外 |
| 输入框「+」 | 去掉常驻灰底，默认裸字形，hover 才出底（与麦克风同一个 token）；字形缩到与整行同档；再向审查 chip 拉近 8px（视觉间距 4px） | 一行控件里只有它常驻底色，等于把「可点」画成了「已选」；裸字形之后，原先被底板衬住的 11px 加号成了整行最重的图标；12px 盒间距在「裸字形 + 带内距的 chip」之间会读成约 27px，左簇因此被拉散；拉近到视觉 4px 才读成一簇 |
| 视图切换入口 | 顶部标签行整条移除，header 从 76px 收到 51px；「轨迹」改为状态行第一项（列表图标 + 视图名），在轨迹页原地变成「对话」 | 只有两个视图时，常驻 36px 的标签行 + 右侧「…」是在为低频功能付固定成本；状态行本来就是本会话读数所在，宽度成本为零。入口做成双向的，是因为移除标签行后不能再有第二个「对话」入口 —— 但也不该为回程新开一条 40px 的 header 行 |
| 队列消息卡片 | 浅灰 `#f5f5f5`（暗色沿用浮层材质） | 它借的是浮层材质上色，浮层改成近白后它和白画布分不开；但它不是浮层 —— 它在画布上叠一层，该用「比画布深一档」而不是「和浮层一样白」 |
| 长用户消息折叠 | 20 行（19 行正文 + 独占一行的「…」）+ 气泡内底部「展开／收起」；阈值按渲染行数；展开原位 | 参照本机 Codex：省略号单独占一行、按钮留在气泡填充里，气泡才仍读作**一个对象**（按钮放到气泡外会读成第二个对象、第二条消息）。按行数而不是字数，是因为窄窗口下 600 字只排 9 行、宽窗口下能排 30 行 —— 字数阈值在响应式布局里等于没有阈值。按钮文字用 `label-secondary` 而不是应用 disclosure 行的 `label-tertiary`：它坐在气泡浅蓝填充上，13px 下 tertiary 的对比度不足 4:1。展开状态**不跨节点保留**：切会话、热更新重挂后重新折叠，不为了"恢复阅读位置"去持有状态 |
| 流式回答的阅读位置 | 正式回答**正在写正文**时继续跟随；到本轮消息顶边抵达「原生内距线」就冻结，之后回答再长也不移动视口。**思考阶段一律不冻结**：模型在写推理时继续跟随，哪怕本轮消息已经越过那条线 | 先做过「回答一开始就冻结」，反馈是「我还没读到就停了」；跟随到吸顶才是原始诉求。线不写死：取会话列表自身的 `padding-top`（原生 `.scroll{padding:16px}`），也就是新会话首条消息距顶的距离 —— 「吸顶」在这个界面里的原生定义。思考阶段单独点名，是因为「正文」这个词的边界在人那里很清楚、在判据那里不清楚：只有把「写推理时不冻结」写进规则，才不会退化成「本轮有内容就冻结」 |
| 「回到底部」按钮 | 按几何显示：`scrollTop + clientHeight < scrollHeight - 2` 才出现 | DSH 只按 `!followingTail` 渲染，与「下面有没有内容」无关。读者读得懂的信息是「下面还有东西」，不是状态机在不在尾部 |
| 首轮就冻结 | 新会话第一轮从第一行起就不自动下滚 | 消息本来就在列顶，冻结线一开始就已到达；这是规则的直接结果，不是例外 |

## 验收与回滚

- **验收**：`component` 补丁的报告 token 全部 `discovered`；`behavior` 补丁看
  `__vtInterface.behaviors()` 的 `installed === total` 与各自的读数；视觉差异只用探针读到的
  计算值判断，不靠肉眼描述。
  方法见 `docs/VERIFY.md`。
- **回滚**：关闭或卸载插件。token 覆盖层随之撤销、注入的 `<style>` 被移除、诊断钩子清除。
  Harness 本体从未修改，所以没有需要清理的残留。
